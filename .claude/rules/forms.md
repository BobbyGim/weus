# Forms & Keyboard

입력 화면은 키보드를 다루는 방식이 두 가지다. 화면에 맞게 고른다.

| 방식 | 쓰는 화면 | 키보드가 올라오면 |
|---|---|---|
| **화면 고정** (네이버 로그인처럼) | 로그인 (`sign_in_page.dart`) | 화면은 그대로, 키보드가 아래쪽을 덮음 |
| **버튼이 키보드 위로** | 회원가입, 그룹 만들기·수정, 코드로 참여 | 화면이 줄어들고 맨 아래 버튼이 키보드 바로 위로 올라옴 (가려지면 스크롤) |

## 화면 고정 (로그인)

```
┌──────────────┐
│ 로고          │ ┐ 위 묶음: 아래 묶음을 뺀 나머지 높이 전부
│ 이메일        │ │ 로고는 남는 높이 가운데, 모자라면 줄어듦
│ 비밀번호      │ │
│ 로그인 버튼   │ ┘
│              │
│ 소셜 로그인   │ ┐ 아래 묶음: 항상 맨 아래 (키보드가 덮어도 되는 것만)
│ 회원가입      │ ┘
└──────────────┘
```

- `Scaffold(resizeToAvoidBottomInset: false)`: 키보드가 올라와도 화면을 줄이지 않는다.
- 스크롤 뷰 없이 `Column`으로 위·아래 묶음을 나눈다. 위 묶음은 `Expanded` 안의 `Column`이고, 그 안의 로고를 `Expanded` + `FittedBox(fit: BoxFit.scaleDown)`로 감싸 로고가 남는 높이의 가운데에 원래 크기로 놓이고, 공간이 모자라면 로고만 줄어든다. 그래서 어떤 화면에서도 오버플로가 나지 않는다.
- 키보드에 가리면 안 되는 것(입력칸, 주 버튼)은 위 묶음에, 가려져도 되는 것(소셜 로그인, 링크)은 아래 묶음에 둔다.
- 아주 작은 화면(iPhone SE 1세대)에서는 주 버튼이 키보드에 걸칠 수 있다. 마지막 입력칸에 `textInputAction: done` + `onSubmitted`를 달아 키보드의 완료로도 제출되게 한다.

## 버튼이 키보드 위로 (그 밖의 입력 화면)

- `CustomScrollView` + `SliverFillRemaining(hasScrollBody: false)` 안에 `Column`, 입력칸 뒤에 `Spacer`와 버튼을 둔다.
- 화면에 다 들어가면 스크롤되지 않고(`ClampingScrollPhysics`), 키보드에 가려질 때만 스크롤된다.
- 그룹 만들기는 버튼이 항상 보이도록 `Column` 안에 `Expanded(ListView)`(입력칸)와 버튼을 두어, 입력칸만 스크롤되고 버튼은 맨 아래에 고정된다.

## 공통

- **입력칸 밖을 누르면 키보드가 내려간다.** `main.dart`의 `MaterialApp.router` builder에서 앱 전체에 한 번 처리한다 (Flutter는 모바일에서 기본으로 안 해 줌). 버튼·입력칸을 누르면 그쪽이 탭을 가져가서 영향이 없다.
- 바텀시트 안의 폼(그룹 수정, 일정 등록)은 `MediaQuery.viewInsetsOf(context).bottom`만큼 아래를 띄워 버튼을 키보드 위에 둔다.
